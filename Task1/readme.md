## Планирование: анализ, идентификация проблем и поиск решений

### Анализ текущих и потенциальных проблем  

1. Проблемы с заказами  
  Клиенты жалуются что они не получили заказ и над их изделием работают дольше обещанного.  
  Проблема скорее всего заключается в том, что теряются сообщения об изменении статусов заказа.
2. Долгая загрузка первой страницы MES с заказами.
3. MES долго рассчитывает стоимость, вплоть до 30 мин.
4. MES не масштабируется.
5. CRM не масштабируется.
6. Нет автоматических тестов, только ручные.
7. Недостаточный мониторинг и логирование.
8. Нет API шлюза.

### Инициативы, которые необходимы для устранения проблем  

*Все инициативы описаны в порядке их приоритета.*

1.  MES является сильнонагруженным сервисом, поэтому его нужно разбить 2 микросервиса - Основное прилождение MES и сервис расчета стоимости изделия.  
  Сервис расчета стоимости изделия самый нагруженный, так как выполняет долгие и сложные расчеты.  
  Этот сервис должен масштабироваться в первую очередь.  

2. Добавить API шлюз.  
   Приложение в целом не может масштабироваться, плохая наблюдаемость и нет кеширования.  
   Так же проблемы с тестированием и внедрением новых версий сервисов.  
   API шлюз поможет справиться с этими проблемами.

3.  Встроить механизмы кеширования и репликации на чтение.  
   Долгая загрузка первой страницы MES с заказами приводит к тому, что заказы не успевают вовремя принять и отправить на обработку.  
   Нужен механизм репликации БД на чтение или кеширование данных.  
   Можно попробовать декомпозировать фронтэнд на микрофронтенды.

4. Настроить автоматические тесты.

5. Улучшить DevOps для автоматизации развертывания новых версий.

6. Внедрить мониторинг и логирование.  
   Повысит наблюдаемость и своевремменное обнаружение новых проблем.

7. Настроить автомасштабирование сервисов CRM и MES.

### Целевая архитектура через полгода

Через полгода хотелось бы видеть:
- Основной сервис MES и сервис расчёта стоимости изделия.
- Более быструю и стабильную загрузку первой страницы MES.
- Автоматические тесты.
- Улучшенный DevOps.

### Три пункта инициатив на ближайшие пол года

- Выделить в отдельный сервис расчета стоимости изделия.
- Добавить API шлюз.
- Встроить механизмы кеширования и репликации на чтение.
